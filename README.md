# tg-assistant

Личный юзербот для Telegram на [Telethon](https://docs.telethon.dev): работает
от моего аккаунта, удаляет сообщения собеседников (у обоих) и отвечает
заготовками на сообщения с ключевыми словами.

## Команды

При первом запуске бот создаёт приватную группу «Ассистент», где кроме тебя
никого нет. Это служебный чат: команды пишутся там, ответы приходят туда же,
«Избранное» не трогается. Чат, к которому относится команда, указывается
первым словом: `@username`, `+телефон` из контактов или `#id` из `.rules`.

| Команда (в служебном чате) | Что делает |
|---|---|
| `.mute @user` / `.unmute @user` | удалять все новые сообщения от него / перестать |
| `.reply цена, прайс => Цены в закрепе` | автоответ на эти слова во всех личках |
| `.reply @user цена => ...` | автоответ только в чате с ним |
| `.filter [@user] казино, ставки` | удалять входящие с этими словами |
| `.del @user N` | удалить его последние N сообщений (до 100) |
| `.rules [@user]` | список правил |
| `.unrule N` | удалить правило |
| `.help` | справка |

Прямо в переписке:

| Команда | Что делает |
|---|---|
| `.del` (ответом на сообщение) | удалить это сообщение у обоих |
| `.del N` | удалить последние N сообщений собеседника |

Остальные команды в переписке тоже работают (без `@user`, для этого чата),
но удаляются сразу и молча. В служебный чат приходят только ошибки и вывод
`.rules`/`.help`. Собеседнику на долю секунды может прийти уведомление
с текстом команды, поэтому правила лучше задавать из служебного чата.

Ключи сравниваются целыми словами без учёта регистра. Один и тот же
автоответ уходит в чат не чаще раза в `REPLY_COOLDOWN_SECONDS`, ботам бот не
отвечает. В группах чужие сообщения удаляются, только если ты там админ.
Если удалить служебный чат, при следующем запуске бот создаст новый.

## Запуск на сервере (netcup, рядом с expense-tracker)

1. Получить `api_id` и `api_hash` на https://my.telegram.org в разделе API development tools.
2. На сервере:
   ```bash
   git clone <repo> ~/tg-assistant && cd ~/tg-assistant
   cp .env.example .env   # вписать API_ID и API_HASH
   chmod 700 data
   docker compose run --rm bot python -m bot.login   # телефон, код, пароль 2FA
   ./deploy.sh
   ```
3. Логи: `docker compose logs -f bot`.

Портов бот не открывает и с nginx expense-tracker не пересекается.

`data/assistant.session` даёт полный доступ к аккаунту: не коммитить, не
копировать. Если сервер скомпрометирован, завершить сессию в Telegram:
Настройки → Устройства.

## Локально

```bash
uv sync
uv run pytest
uv run python -m bot.login && uv run python -m bot.main
```
